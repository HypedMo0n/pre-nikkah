## Breaking changes applied

1. React and React DOM moved to the React 19.2 line required by Next.js 16.
2. The Supabase server factory now awaits the asynchronous `cookies()` API.
3. Root `middleware.ts` became `proxy.ts`, and the session helper was renamed
   accordingly. The Proxy copies refreshed cookies and Supabase cache-control
   headers to redirects.
4. Protected-route checks use a verified Supabase claims request in Proxy.
   Server code still performs its own authorization and does not trust route
   protection as the data-access boundary.
5. The removed `next lint` workflow was replaced with ESLint 9 and the Next.js
   flat configuration. ESLint 10 was evaluated but rejected because the bundled
   React plugin was not compatible with its removed context APIs.
6. The production build now uses Turbopack by default. The repository has no
   custom webpack configuration and needed no opt-out.
7. Next.js updated TypeScript to the React automatic JSX runtime and ES2017
   target. Strict mode remains enabled.
8. No existing page used synchronous `params`, `searchParams`, or `headers()`.
   New routes must use their asynchronous Next.js 16 forms.
9. Existing authenticated pages remain dynamically rendered. Future Server
   Actions and Route Handlers must authenticate independently and return
   explicitly non-cacheable private responses.
10. Node.js 24.18 satisfies the Next.js 16 minimum of Node.js 20.9. Vercel's
    Node runtime remains the target.

No database migration was required by the framework upgrade. Database changes
in this phase implement onboarding, privacy, invitation, comparison, reveal,
and deletion requirements independently of the framework change.

## npm audit before and after

Before the upgrade, npm reported five vulnerabilities: four high and one
moderate. The high findings affected the old Next.js line and the old ESLint
dependency chain. The moderate finding affected PostCSS.

After the upgrade, npm reported two moderate entries and no high or critical
findings:

| Package | Severity | Installed | Patched | Dependency | Exposure | Assessment and remediation |
| --- | --- | --- | --- | --- | --- | --- |
| `next` | Moderate | 16.2.10 | No valid patched Next.js version reported by npm | Direct | Runtime package, finding is inherited from nested PostCSS | npm's suggested downgrade to 9.3.3 is not a valid remediation. Upgrade to the official patched maintained release when available. |
| `postcss` | Moderate | 8.4.31 nested under Next.js | 8.5.10 | Transitive | CSS processing path packaged with Next.js; this app does not stringify user-controlled CSS | Root PostCSS is already 8.5.19. Do not add an override. Upgrade Next.js when it ships a patched nested dependency. |

The PostCSS advisory is `GHSA-qx2v-qp2m-jg93`, an XSS issue when stringifying
an unescaped closing style tag. The current application compiles developer-owned
styles and does not accept private answers or other user content as CSS, which
limits practical exposure, but the advisory remains open. No forced audit fix
or package override was used.
